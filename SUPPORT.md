# Support

NeuroDecodeKit is pre-1.0 research software maintained on a best-effort basis.

## Where To Ask

- Use **Bug report** for a reproducible software defect.
- Use **EEG data compatibility** for a metadata-first dataset or local-file
  question. Do not attach recordings.
- Use **EEG hardware qualification** for a headset, board, SDK, replay, timing,
  or packet-loss proposal.
- Use **Research result** for a bounded result with a frozen split, controls,
  resources, and claim boundary.
- Use a plain feature issue only when no structured form fits.
- Follow `SECURITY.md` for sensitive security or data-exposure reports.

Before filing, search existing issues and read `README.md` plus
`CONTRIBUTING.md`.

## What Maintainers Can Help With

- installing the package and optional extras;
- understanding schemas, CLI commands, and refusal messages;
- constructing a synthetic fixture for a format condition;
- scoping a bounded data, device, or evaluation protocol;
- reviewing split leakage, no-signal controls, and proof language;
- interpreting what an existing result does and does not establish.

## What Maintainers Cannot Provide

- medical, diagnostic, therapeutic, or safety-critical advice;
- certification that a device can decode speech or thoughts;
- private storage or review of participant recordings through GitHub;
- permission to use third-party data or code beyond its license;
- access to unreleased Brain2Qwerty v2 data or embeddings;
- guaranteed response times or custom model-development services.

Include the exact commit, operating system, Python version, installed extras,
command, expected behavior, observed behavior, and a synthetic reproduction.
Redact paths, identifiers, event content, and credentials before posting.
