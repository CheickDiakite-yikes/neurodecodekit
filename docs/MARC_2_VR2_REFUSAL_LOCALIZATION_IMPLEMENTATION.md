## Findings

The audit reached `MARC2VR5-R2` and proved two separate engineering defects.

First, VR4P catches `LiveDomainEligibilityRefusal` but never reads
`exc.route`. All eight VR2 refusal classes are mapped to outer
`MARC2MSP-F07` with the same message. That reduces eight aggregate-safe
diagnostic classes to one and explains why the consumed run cannot tell us
which VR2 stage refused.

Second, VR2's live path calls `_assert_selection`, which compares every real
selection against nine exact values frozen from the generated fixture:

```text
selected_subjects
selected_run_bundles
selected_core_members
fit_run_bundles
heldout_run_bundles
fit_heldout_overlap
selected_reservation_bytes
reservation_cap_bytes
selection_identity_sha256
```

The generated success matrix intentionally holds those values constant across
four exclusion profiles and two row orders. The real path therefore does not
accept a general maximal rank prefix measured from real compressed sizes; it
requires the measured result to reproduce the generated `16`-subject,
`8,105,207,776`-byte identity.

The same path also emits:

```text
source_id:          freewill_23_generated
proof_posture:      generated_fixture_selection_only_no_scientific_value
source hash key:    generated_inventory_sha256
```

Those labels are wrong for a future real structural cohort even if every
source, eligibility, split, and reservation invariant passes.

## What This Does Not Prove

The consumed private route remains unavailable. The audit does **not** claim
that VR4P reached `MARC2VR2-F06`; `F02`, `F03`, or `F04` may have fired first.

Committed producer identity, transport hashes, row counts, the exact source
hash pass, and strict JSON parse are consistent with the VR2 envelope. That
constrains `F02`, but it does not formally identify or exclude the hidden
route without prohibited private reinspection.

No private source row was opened, parsed, inferred, or reconstructed.

## Smallest Repair

The next lane should be generated-only and additive. It should:

1. preserve `exc.route` as an aggregate failure code while discarding its
   reason and all private values;
2. preserve full source validation before selection;
3. accept any measured maximal contiguous rank prefix from 12 through 19
   subjects under the unchanged 8 GiB reservation cap;
4. derive bundle/member/split counts from that measured subject count;
5. require the selected reservation to be within cap and either prove the next
   participant does not fit or that all 19 fit;
6. emit live source identity, proof posture, and source-hash vocabulary;
7. freeze the measured real selection identity only after one future success;
   and
8. exercise multiple generated reservation boundaries before any new private
   request.

The consumed VR4P executor remains immutable and cannot be patched or reused.
This exact implementation is remotely green. The repair now needs its own
frozen contract and generated qualification. A later private pass remains a
new Tier C action with a separate all-false packet and fresh maintainer
decision.
