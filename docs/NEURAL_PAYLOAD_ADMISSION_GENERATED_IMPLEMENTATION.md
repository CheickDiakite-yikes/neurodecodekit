## Purpose

NPA1-G prevents a future one-shot neural-data gate from being spent on basic
delivery behavior. It qualifies transport rules with inert generated bytes
before any source-specific metadata, canary, sensor header, acquisition, or
model operation is allowed.

This module contains no live network opener and no real execution command.
Its public CLI has only `plan` and `qualify-generated`.

## What Was Implemented

`src/neurodecodekit/datasets/neural_payload_admission.py` separates five
layers:

1. stable scientific source identity, including revision, object key, full
   object byte count, and full object SHA-256;
2. expiring signed transport capability identity;
3. HTTPS route and HTTP framing admissibility;
4. bounded body or range-segment identity; and
5. unavailable later semantic sensor eligibility.

The generated transport path validates exact `Accept-Encoding`, `User-Agent`,
and range request headers on every hop. It permits only zero, one, or two
bodyless HTTPS redirects to allowlisted, globally routed generated hosts. It
rejects automatic redirects, loops, downgrade, userinfo, nondefault ports,
fragments, host and path drift, malformed signed queries, expired or excessive
capabilities, duplicate critical response headers, encoding drift, framing
ambiguity, invalid ranges, incomplete or overflowing bodies, read and close
failures, retries, extra transcript responses, and public-report mutation.

Body reads are incremental until EOF or cap-plus-one. A 206 profile must prove
`0 <= start <= end < full object size`, exact segment length, exact
`Content-Range`, exact segment SHA-256, and consistency with the separately
bound full-object identity. A refreshed signature may change the delivery
capability while leaving the source and stable transcript identities unchanged.

Only exact `FixtureOpener`, `FixtureResolver`, and `FixtureMetrics` instances
can enter the generated executor. A socket-denial test confirms that the full
qualification reaches neither socket creation nor DNS.

## Independent Review

An independent reviewer found five initial blockers: internally impossible
range profiles, a bypassable report validator, one-read EOF assumptions,
literal rather than temporal expiry handling, and an overly broad injected
callable boundary. All were fixed and covered by tests. A second review found
a forgeable valid-hex transcript digest and nonexact mutation routing; both
were pinned with exact substitution tests. The final review reported no
remaining blocker in scope, and all 13 focused tests passed.
