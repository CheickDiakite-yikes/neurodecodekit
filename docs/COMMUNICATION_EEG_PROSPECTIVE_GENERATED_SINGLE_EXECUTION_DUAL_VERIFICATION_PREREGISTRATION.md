# COMM-P0-G Single-Execution Dual-Verification Rehearsal Preregistration

Recorded: 2026-08-28

Status: frozen generated-only Tier B rehearsal contract; implementation and
execution have not occurred.

Gate: `COMM-P0-G-FS3-v0`

Run identity: `COMM-P0-G-FS3-R0`

## Question

Can one exact full-scale fictional producer execute the frozen COMM-P0 model
schedule while a separate, model-free child independently verifies its
immutable prediction transcript, target firewall, and aggregate score within
the unchanged 180-second resource envelope?

This is an engineering proof question. A pass would not activate or consume
the official qualification and would have no scientific value.

## Why this successor is prospective

The consumed `COMM-P0-G-FS2-R0` rehearsal completed one full fictional replay
but could not complete a second equivalent full numerical replay before the
shared 180-second deadline. It parked at 180.05074683297426 seconds. Peak RSS,
storage reservation, process monitoring, cleanup, and every zero-operation
gate passed. The measured bottleneck was duplicated full model execution, not
memory or storage.

Amendment 3 therefore replaces only redundant full-scale fitting. It preserves
one complete 42-participant schedule and adds a genuinely independent
verification surface with no model capability. Reduced two-process model
replays preserve deterministic implementation qualification before any full
rehearsal. FS2 remains immutable and consumed; FS3 is a new gate and run ID,
not a repair, retry, resume, or reinterpretation.

## Immutable parents and proof anchors

FS3 binds the original generated qualification, Amendments 2 and 3, the exact
official-coordinator proof closeout, and the consumed FS2 result. Amendment 3
commit `b15d3cf86fc4d6234d64c3a19cca394e72f43fc6` passed Base Python job
`98860211722`, Optional Neuro Readers job `98860211949`, and CI
`33174711145`, then reached GitHub `main` before this registration was created.

The frozen model, features, source-only nuisance fits, participant-held-out
folds, endpoint rules, thresholds, penalties, controls, and claim boundaries
must not change. The existing official activation lock and consumed-marker
surface remain inaccessible.

## Ordered barriers

1. This preregistration, machine contract, and tests must be committed, pushed,
   pass both required CI jobs, and be present on GitHub `main`.
2. An additive FS3 wrapper and CLI may then be implemented and qualified only
   with generated reduced or mocked fixtures. No 21-person-per-cohort model
   run may occur during implementation or CI.
3. Qualification must produce two isolated model replays with at most three
   fictional participants per cohort, byte-equivalent canonical surfaces, and
   all 70 refusal families in each replay, for 140 refusal observations total.
4. The exact implementation and proof must be committed, pushed, pass both CI
   jobs, and be present on GitHub `main`.
5. One nonofficial FS3 attempt may then create a durable no-replace receipt and
   run one full producer child followed by one independent verifier/scorer

   the attempt. No retry, rerun, resume, repair, or substitution is allowed.
6. Only a consumed `FS3_PASS` may support a later, separately registered
   official activation. FS3 itself never activates the official qualification.

## Independent verifier/scorer

The verifier must run after the producer in a distinct sanitized process and
isolated work directory. Its capability tree must contain no model, fit,
transform, inference, threshold-selection, calibration, prediction-creation,
language-model, or parameter-update operation.

Using no-follow descriptors, it must independently verify:

- contract, amendment, implementation, transcript, and scorer identities;
- prediction stream ordering, cardinality, uniqueness, and file identity;
- the freeze HMAC, inventory digest, and target-delivery nonce;
- finite normalized probabilities and mandatory missing/duplicate penalties;
- exactly 42 participants, 17 conditions, 1,428 prediction sets, and 91,392
  prediction rows in the frozen producer transcript; and
- two independently delivered generated cohort target envelopes after freeze,
  producing two aggregate scores exactly equal to the producer scores.

The verifier must reject assigned scorer, freeze, inventory, descriptor,
capability, nonce, probability, duplicate, missing-row, path, and publication
mutations without mutating accepted state. Public output may contain only
aggregate target-free counters, digests, resource measurements, route, and
warnings. It may never contain an individual prediction, probability, target,
label, participant outcome, private path, key, or generated payload.

## Resource envelope

- one CPU thread, one worker, and one numerical job;
- one full producer and one model-free verifier, strictly sequential;
- distinct process IDs, isolated work directories, and concurrency maximum one;
- 180 seconds total wall time including receipt, setup, producer, verifier,
  scoring, publication, and cleanup;
- 536,870,912-byte peak parent-plus-child process-tree RSS;
- 537,919,488-byte aggregate incremental-disk ceiling;
- 268,435,456-byte temporary-disk peak;
- 1,048,576-byte public aggregate result ceiling;
- zero retained generated payload bytes;
- zero network requests and bytes; and
- at least 22,012,755,968 free bytes before reservation, leaving at least
  21,474,836,480 bytes, exactly 20 GiB, afterward.

Continuous process-tree monitoring is mandatory. Zero samples, a missing
descendant, cap breach, reservation failure, output collision, or cleanup
escape is a consumed refusal.

## One-shot receipt and outcomes

FS3 uses a new durable, no-replace receipt schema and path. The receipt must be
created before the producer begins and must be rejected by the official
activation loader. It may contain only public gate identity, attempt identity,
bound hashes, start time, and aggregate status. FS3 may not read, create,
replace, rename, or delete an official consumed marker.

`FS3_PASS` requires the exact producer schedule, independent verifier match,
all refusal and resource gates, atomic no-replace publication, and total
runtime at or below 180 seconds. Any other post-receipt outcome is `FS3_PARK`.
Either route consumes `COMM-P0-G-FS3-R0` and permits no rerun.

## Claim boundary

Engineering capability this rehearsal can establish: one complete fictional
model schedule can be independently verified and rescored by a separate
zero-model process under the frozen resource envelope.

Scientific claim this rehearsal cannot establish: no real EEG or human target
is accessed, so it cannot demonstrate communication decoding, EEG information
beyond peripheral controls, unseen-person generalization, independent
replication, causal live decoding, hardware performance, or clinical value.
