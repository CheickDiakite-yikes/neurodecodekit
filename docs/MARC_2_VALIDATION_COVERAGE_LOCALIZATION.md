## Short Answer

The second live selection attempt did not merely hit an unknown data problem.
The committed generated fixture and live validator cover different source
domains.

The published source-space registry describes 23 participants and 238 runs.
The eligible session-1/2 subset contains 19 participants and 195 runs. The
generated fixture creates only those 195 eligible run bundles, or 780 required
four-file companion rows, then fills the remainder of its 1,025 regular-file
rows with 245 generic auxiliary names.

That means 43 published run slots, corresponding to 172 four-file companion
slots, were never represented as Freewill-shaped adversarial rows in the
fixture that qualified LA1.

```text
published source space:                  23 participants / 238 runs
eligible session-1/2 subset:             19 participants / 195 runs
published space outside eligible subset:  4 participants /  43 runs
required companions per run:              4
generated eligible companion rows:      780
published-space companion slots:        952
generated coverage gap:                 172 companion slots
generated generic auxiliary rows:       245
```

At the same time, LA1 groups every Freewill-shaped source row and requires the
global group count to equal exactly 195 before it looks up the eligibility
map. A structurally valid excluded participant, extra session, or later run can
therefore make the live source fail even though that row should simply be
ignored for selection.

This is a generated-coverage and validation-order defect. It is consistent
with the consumed `MARC2LAR-F02` class, but it does not reveal or claim the
exact private predicate that fired.

## Prospective Repair

The next generated-only design should change the boundary, not merely adjust a
number:

1. Validate general ZIP and BIDS safety for every source row.
2. Separate source validity from selection eligibility.
3. Filter to eligible participants and sessions before comparing the exact
   195-run eligible inventory.
4. Permit valid excluded participants, extra sessions, and later runs while
   keeping them ineligible for selection.
5. Represent all 43 omitted published run slots as Freewill-shaped generated
   adversaries instead of generic auxiliary files.
6. Preserve the target-free rank, session split, reservation formula, and cap.
7. Emit preregistered aggregate-safe predicate codes without publishing source
   values, so a future one-shot refusal is diagnosable without reinspection.

This is a prospective generated-fixture repair only. It does not patch, retry,
resume, or reuse LA2. A future private read still requires a separately named
contract, remotely green implementation, and fresh Tier C decision.
