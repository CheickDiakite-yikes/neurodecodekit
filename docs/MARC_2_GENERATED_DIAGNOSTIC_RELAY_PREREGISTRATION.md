Date: 2026-08-16

Lane: `MARC2-VR8B`

Status: **Frozen generated-only Tier B contract; implementation pending**

## Question

Can the exact central-directory parser, live manifest composer, VR2 validator,
and VR6 adapter be connected in one full-scale generated path that preserves
both allowlisted refusal codes and distinguishes F02, F03, and F04 without
emitting a reason, path, identity, or private value?

VR8A narrowed the consumed unknown to F03 versus F04, but it also found two
engineering gaps: VR7P dropped VR6's nested route field, and existing VR2
success fixtures bypass the exact 1,227-row parser/producer boundary. VR8B
repairs only those generated-test gaps. It does not reopen VR7P or identify the
consumed private route.

## Frozen Composition

The implementation must be a new dependency-free module. It may import the
green exact parser, green live manifest composer, VR2, VR6, VR1, and frozen
selector. It must not import, call, patch, alias, or modify consumed VR7P.

The full-scale generated source is constructed in this order:

1. Build one registered VR2 profile-A source only as a generated blueprint for
   1,227 safe member names, kinds, methods, and compressed-size budgets.
2. Convert every row into an exact parser `EntrySpec` with zero comments,
   deterministic nonoverlapping local intervals, and ZIP64 only where required
   by an offset or size.
3. Build and parse the resulting synthetic ZIP64 central directory through the
   exact central-directory implementation and generated transport wrapper.
4. Compose the six-field live manifest with the exact live producer helper.
5. Replace only the generated transport-body digests with the three registered
   live digest values required by VR2. This explicit synthetic normalization
   may not alter entries, schema, version, proof posture, or source identity.
6. Pass the resulting in-memory object through VR6, which invokes VR2 before
   any selection logic.

No member local header or member payload is created or read. The virtual
archive identity may remain large, but all materialized generated bytes must
remain below the frozen cap.

## Frozen Route Matrix

The qualification must run each case in canonical and reversed central-
directory order and replay the complete matrix exactly:

| Case | Generated mutation point | Expected result |
|---|---|---|
| `success` | none | VR6 success after exact parser and producer traversal |
| `F02` | change one live-envelope identity value after composition | outer `MARC2VR6-F02`, nested `MARC2VR2-F02` |
| `F03` | change one suffix-bearing task token before exact parsing | outer `MARC2VR6-F02`, nested `MARC2VR2-F03` |
| `F04` | rename one complete four-companion bundle to an unknown participant before exact parsing | outer `MARC2VR6-F02`, nested `MARC2VR2-F04` |

The relay may publish only the case identifier, success/refusal disposition,
outer VR6 code, nested VR2 code, and aggregate counts/hashes. It must discard
exception text, safe reasons, member names, participant/session/run values,
and all source rows.
