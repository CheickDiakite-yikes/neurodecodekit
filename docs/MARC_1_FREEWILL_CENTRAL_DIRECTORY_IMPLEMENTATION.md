## Virtual Archive Mechanics

The fixture represents the exact registered 13,591,548,048-byte archive while
materializing only 280,249 generated bytes. It contains:

- one exact 128-KiB generated tail;
- one 148,910-byte generated central directory;
- a misleading EOCD signature inside the ZIP comment;
- a reconciled classic EOCD, ZIP64 locator, and complete ZIP64 EOCD inside the
  tail;
- eighteen central-directory entries: four directories and fourteen regular
  files;
- compression methods 0 and 8, one UTF-8 path, CP437 paths, and exactly one
  ZIP64 extended member; and
- zero local-file headers and zero member payload bytes.

The parser uses standard-library `struct`; it does not use `zipfile` to parse
the directory. It searches backward for a structurally valid EOCD, validates
single-disk ZIP64 bounds, parses every central entry, resolves ZIP64 values in
field order, and refuses trailing bytes or entry-count and byte-count drift.

Member names must decode strictly, normalize to NFC, remain unique and
POSIX-relative, and contain no absolute path, backslash, drive prefix, empty
component, repeated separator, raw `.` or `..` component, control character,
or NUL. Only regular files and directories using methods 0 or 8 are allowed.
Data-descriptor bit 3 may be inventoried because no descriptor or local header
is opened. Encrypted, patched-data, strong-encryption, masked-header,
unsupported, multi-disk, malformed-extra, and unknown-file-type states fail
closed.
