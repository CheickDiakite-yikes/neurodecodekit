## Purpose

`R1-G` is the reversible engineering gate required by
`FMSR1-DISCOVERY-M0-A1`. It must prove, using only generated bytes and injected
responses, that a future executor can fail closed around three authority
surfaces:

1. source-global revision evidence;
2. complete opaque snapshot replay evidence; and
3. exact attempt-specific GitHub CI evidence.

It also qualifies the consumed-marker ordering needed before a future
irreversible invocation. Passing this gate cannot authenticate GitHub, admit a
real source, contact an official index, or move any scientific coordinate.

## Opaque Complete Snapshot Mode

`OPAQUE_COMPLETE_SNAPSHOT_REPLAY` uses one ordered `pages[]` structure. Each
page keeps its ordinal, exact request identity, redirect transcript,
pagination identity, raw response byte count and SHA-256, next-request
identity, and terminal state together in one record. Parallel arrays are
forbidden.

The sequence must start at zero, contain no gap, duplicate, cycle, fork, or
reorder, and end in exactly one terminal page with no next request. Redirects
and pagination are explicit. The validator may hash generated response bytes
but must never parse, retain, rank, or select candidate content. A generated
poison-candidate fixture must pass without its candidate subtree being
accessed.

The generated profiles cover all five frozen index IDs and both modes. These
fixture assignments do not choose or admit a mode for a real source.

## Consumed Marker And Ordering

The generated marker implementation must operate only inside a fresh
qualification-created temporary directory. It must:

- reject a symlink or non-directory parent;

- `fsync` the file before close;

- allow exactly one creator while every later create refuses before network.

process exit, or mutable handoff refuses. Cleanup is limited to the fresh
